# 开发路线图

TD Open 的长期目标是覆盖实时视觉创作、信号处理、3D、交互装置和 AI 工作流。当前交付是一套可运行、可扩展的早期基础，距离 TouchDesigner 全功能覆盖仍有显著差距。以下是开发方向和验收标准，不是已经完成的功能，也不是交付日期承诺。

实际支持情况以 [功能矩阵](FEATURE_MATRIX.md) 为准。兼容商业软件文件格式、接口或 GPU 行为，需要独立的技术设计与验证；不能从节点同名推断兼容。

## 阶段 0：可编辑、可运行、可保存的创作闭环

范围：节点画布、中文参数说明、实时输出、示例项目、图像与基本信号节点、轻量 3D、项目保存与 JSON 交换、AI 服务商配置、生成结果和 MCP 工具入口。

验收：一个新用户能够从模板开始，修改参数、增加节点、连接输出、保存并重新打开项目。没有外部 AI 密钥时，视觉编辑器应独立可用。远程服务不可用时，界面应保留项目并呈现错误。

这一阶段形成现有仓库的基础。具体实现深度及尚未验证的部分见功能矩阵，不能把基础节点数量当作原软件覆盖率。

## 阶段 1：完善新手体验与可靠项目结构

- 增加分步骤入门、可搜索的节点说明和每个节点的最小例子。
- 统一类型化端口、错误提示、参数范围、撤销与重做、自动保存和项目迁移。
- 建立资产清单、项目相对路径、资源缺失修复和可携带项目包。
- 增加参数动画、信号到参数的显式绑定、选择/合并/限制/延迟等信号节点。
- 完善实际音频输入、频谱、包络、节拍分析和对音频设备权限的解释。

验收：已有版本项目可迁移；相同项目重新打开后产生一致的静态输出；断线、错误端口和资源丢失都有明确定位。音频演示与实际设备输入必须明确区分。

## 阶段 2：可扩展的实时计算引擎

- 从当前基础渲染过渡到统一的纹理/缓冲区资源模型，减少 Canvas 与 GPU 之间的数据往返。
- 引入依赖调度、脏标记、输出缓存、资源释放、每节点耗时和内存统计。
- 增加明确语义的反馈节点与逐帧缓存；不能将任意循环连接视作合法反馈。
- 支持自定义 GLSL/WGSL、着色器编译错误定位、线性色彩空间、浮点纹理和高分辨率输出。
- 设计点属性/几何属性的数据模型和 GPU 计算路径，逐步补全 POP 类能力。

验收：公开可复现的测试图和硬件条件，报告不同分辨率、节点数下的帧时间与峰值资源使用；节点删除和项目切换不会持续泄漏 GPU 资源。性能目标必须结合测试环境制定，不能笼统保证 4K/60 fps。

## 阶段 3：3D、组件与数据网络

- 扩展几何处理、实例化、相机、灯光、独立材质节点和场景树。
- 支持 glTF 等开放格式的本地导入与生成资产接入，处理外部贴图、坐标系和资源生命周期。
- 增加表格、JSON、文本转换和数据事件节点；脚本节点采用明确隔离方案。
- 增加可嵌套组件、子图输入输出、公开参数、可复用模板和版本管理。
- 补全曲线、关键帧、时间线、事件与演出 cue 等控制机制。

验收：子图可以独立打包并重复实例化；参数变化可在实例间隔离；3D 资产重开后可复现；失败脚本不会阻断渲染或任意访问宿主资源。

## 阶段 4：AI 与 MCP 的完整创作工作流

- 扩展音乐、图像、视频、3D 和文本服务的认证方式、请求模板及响应映射。
- 为长任务引入持久队列、轮询、取消、重试、成本记录和产物缓存。
- 将生成图片、音乐、网格接入相应节点，保存 prompt、模型与可公开的生成元数据。
- 扩展对话图操作、局部修改、解释依赖、故障诊断和可比较的修改预览。
- 完善 MCP 协议版本协商、分页、资源/提示、会话、OAuth 及工具权限。
- 支持工具目录刷新、调用历史、明确错误及可复现的图修改事务。

验收：使用至少一个真实服务验证每种声称支持的生成模态；网络中断不会丢失已有作品；一个失败的图操作不会留下半修改项目。MCP 合规性按具体版本和 transport 测试报告声明。

## 阶段 5：设备、演出输出与桌面分发

- OSC、MIDI、WebSocket、串口、DMX/Art-Net/sACN 等协议适配。
- NDI、Spout/Syphon、采集卡和平台专用视频输出的原生桥接。
- 投影校正、遮罩、边缘融合、多屏输出、帧同步、远程播放与故障恢复。
- 音视频文件解码、录制、离线逐帧渲染、色彩管理和时间码。
- 本地桌面容器、安装包、签名、离线启动与设备权限管理。

验收：每种设备/协议公布实际测试组合；持续运行测试覆盖断连重连；跨平台限制在界面和文档中可见；用于现场演出前完成长时间稳定性测试。

## 发布前横向工作

稳定插件 API、项目 schema 版本、持续集成、单元/集成/浏览器测试、依赖许可清单、可下载示例、贡献流程，以及多语言和无障碍改进。需要远程多人使用时，再补充身份认证、权限、租户隔离、HTTPS、配额和审计；当前本地开发服务不能直接当作公共多租户服务。
