# API 接入总览

这套文档面向第一次配置 API 的使用者，也提供给二次开发者可复制的 JSON、curl 和 Python 示例。说明以 TD Open 0.4 当前代码为准；示例中的模型名和服务地址需要按供应商文档填写。

在软件里从**连接中心 → 接入指南**，或**学习/帮助 → API 接入文档**打开。文档支持搜索、页内目录、代码复制和下载，与仓库中的 Markdown 使用同一份内容。

| 让外部 AI 通过对话操作 TD Open | [MCP 双向接入](MCP_GUIDE.md) | AI 客户端能列出 TD Open 工具，预览并应用图修改 |
| 从 TD Open 调用外部 MCP 工具 | [MCP 双向接入](MCP_GUIDE.md) | 发现工具后，在 MCP 节点手动调用并查看返回值 |

## 先分清三种地址

| 地址 | 谁连接谁 | 例子 |
| --- | --- | --- |
| TD Open 本地 API | 你的脚本 → TD Open | `http://127.0.0.1:8765/api/health` |
| AI 服务基础地址 | TD Open 的 Python 后端 → AI 服务 | `https://api.openai.com/v1` 或你自己的模型网关 |
| MCP 服务地址 | TD Open 的 MCP 客户端 → 外部工具服务 | `http://127.0.0.1:9000/mcp`，须支持 Streamable HTTP |

不要把 TD Open 的 `/api` 地址填到 AI 服务“API 基础地址”里。它们是不同层。

`127.0.0.1` 表示**发起连接的那台机器自己**。如果 TD Open 后端运行在远程 Linux 服务器，它配置里的 `http://127.0.0.1:9000` 指服务器上的 9000 端口，不是你笔记本上的模型服务。浏览器加载媒体时，URL 则必须对浏览器所在机器可达。

实际调用顺序：

```text
AI：浏览器点击运行 → TD Open 后端 → 供应商 API → 本地保存结果/返回 URL → 节点显示
MCP 工具：浏览器点击运行 → TD Open MCP 客户端 → 外部 MCP 服务 → 工具结果
AI 控制：外部 AI 客户端 → TD Open stdio MCP → 本地图 API → 已保存项目 → 编辑器同步
设备：原生设备/SDK → 协议或适配器 → TD Open I/O 服务 → 节点数据
```

## 第一次接入前准备什么

1. 启动 TD Open，确认浏览器可打开 `http://127.0.0.1:8765`。
2. 从供应商的 API 文档取得：**基础地址、具体接口路径、认证方式、模型 ID、请求体和返回体样例**。聊天网页地址不能替代 API 地址。
3. 若是生成服务，确认服务是否同步返回结果；只返回任务 ID 的服务还需要查询任务步骤。
4. 在连接中心按能力分别保存服务。图片服务不能直接在音乐节点使用；一个供应商需要多种能力时建立多条连接。
5. 先用一个短提示词或最小工具参数验证。保存连接只说明配置已保存，**不会主动测试供应商密钥或模型权限**。

## 一条最短的接入路线

1. 打开**连接 → AI 服务**，选择“OpenAI 兼容”或“自定义 HTTP”。
2. 填写服务名称、生成类型、模型名称、API 基础地址和 API Key。自定义 HTTP 再填请求路径与 JSON 请求体模板。
3. 点击“保存服务”。
4. 在节点库添加对应的“AI 文本 / AI 图片 / AI 音乐 / AI 三维”。
5. 选择刚保存的服务，填写提示词，点击节点参数里的运行按钮。
6. 文本查看文字结果；图片连到画面输出；音乐点击播放后接音频/频谱；3D 连到 Render 再接输出。详细端口与播放步骤见 [AI 服务接入](AI_API.md)。

打开案例、加载项目或保存连接不会自动执行付费生成。运行节点才会发出生成请求。配置模型后的“创作助手”发送消息也会请求语言模型。

## 远程服务器的常见情况

通过 SSH 使用服务器时，可在自己的电脑建立转发：

```bash
ssh -L 8765:127.0.0.1:8765 用户名@服务器地址
```

然后浏览器访问 `http://127.0.0.1:8765`。AI 服务连接由服务器发起，所以服务器也要能访问供应商或你的模型网关。若外部 MCP 客户端只支持本地 stdio，可在客户端所在机器运行可导入 `backend` 包的 Python MCP 进程，并通过 `TD_OPEN_APP_URL` 指向已经建立的本地转发地址，详见 MCP 文档。

## 配置与文件存在哪里

默认都在 `/storage/homes/hongzj/dell/td_open`：

| 路径 | 内容 |
| --- | --- |
| `data/config/providers.json` | AI 连接与密钥 |
| `data/config/mcp_servers.json` | MCP 连接、Token、工具权限 |
| `data/projects` | 作品；引用连接 ID，不保存密钥 |
| `data/assets` | 上传素材和 API 返回的 base64 媒体 |
| `data/exports` | PNG、WAV、WebM、JSON 导出 |
| `data/io` | 文件/共享内存协议数据 |
| `docs` | 本文档源文件 |
| `examples/api` | 可公开的配置与演练代码 |

设置 `TD_DATA_DIR` 后，上表 `data/` 下的数据改存到该目录的相同子路径；`docs/` 和 `examples/api/` 仍位于仓库内。数据目录必须在项目根目录内。密钥文件只使用本机文件权限保护，不是加密保险库；不要公开 `data/config`。公开仓库已忽略 `data`、`.cache`、虚拟环境和本机工具。

## 遇到问题先检查什么

按顺序检查：**本地服务健康 → 连接类型和能力 → 地址拼接 → 密钥与模型 → 返回 JSON → 资源 URL/浏览器 CORS**。不要反复点击付费生成来测试一个明显错误的地址。

AI API、MCP 和设备协议各有不同的错误含义，各篇末尾都列了排错表。对不支持的认证、二进制响应、异步任务、设备 SDK，文档会说明需要增加哪一层适配；不能仅凭保存成功推断已经完成接入。
